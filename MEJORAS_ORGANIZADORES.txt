1. QUÉ SE QUIERE (confirmación de entendimiento)
------------------------------------------------------------------------
Hoy el sistema solo consulta la hoja "Inscripciones". Si el DNI no está,
el frontend muestra "NO ESTÁS INSCRITO" y los botones para registrarse.

Se pide:
  a) Cuando el DNI NO se encuentre en "Inscripciones", el backend debe
     revisar una NUEVA hoja llamada "Organizadores".
  b) Si el DNI SÍ está en "Organizadores", mostrar una tarjeta nueva con
     el oso organizador (oso_organizador.png, ya está en el repo),
     indicando nombre y comisión (columna "Organizador").
  c) La columna ID de esa hoja está vacía (el formulario de Google no la
     llena). Al momento de la PRIMERA consulta que encuentre al
     organizador, el script debe GENERAR un ID único y ESCRIBIRLO en su
     fila, para que quede registrado de forma permanente.
  d) Objetivo final: ese ID servirá a futuro para generarles un
     COMPROBANTE/CONSTANCIA de organización (igual que los inscritos
     normales tienen el suyo).

Flujo resultante:
  DNI -> ¿está en Inscripciones? --sí--> tarjeta normal (como hoy)
                |
                no
                v
        ¿está en Organizadores? --no--> tarjeta "NO ESTÁS INSCRITO"
                |
                sí --> generar/asignar ID (si no tiene)
                    -> guardar ID en la hoja
                    -> responder tipo:'organizador'
                    -> tarjeta de organizador con oso_organizador.png

Estructura de la hoja "Organizadores" (encabezados en fila 1):
  ID | Marca temporal | Dirección de correo electrónico | Nombres |
  Apellido Paterno | Apellido Materno | Código | DNI | Celular |
  Organizador        <- comisión/ej: "Actas y Archivos"

2. CAMBIOS EN EL BACKEND (Apps Script .gs)
------------------------------------------------------------------------
2.1 Configuración nueva:
      const ORG_SHEET_NAME = 'Organizadores';

2.2 Nueva función buscarOrganizadorPorDNI(dni):
      - Igual estilo que buscarUltimaPorDNI(): localizar columnas por
        nombre de encabezado (headers.indexOf), NO por posición fija.
      - Columnas necesarias: 'ID', 'DNI', 'Nombres',
        'Apellido Paterno', 'Apellido Materno', 'Código',
        'Organizador'.
      - Buscar la última coincidencia (de abajo hacia arriba).

2.3 Generación del ID (solo si la celda ID está vacía):
      - Formato sugerido:  ORG-0001, ORG-0002, ... (secuencial).
      - Calcularlo como máximo de IDs existentes + 1 (no usar número de
        fila, porque si borran/ordenan filas se rompería).
      - USAR LockService ANTES de leer-maximo-y-escribir, para que dos
        consultas simultáneas no reciban el mismo ID:

          const lock = LockService.getScriptLock();
          lock.waitLock(10000);
          try {
            // releer la celda ID (por si otro proceso ya la llenó),
            // generar ID, setValues en la celda exacta
          } finally {
            lock.releaseLock();
          }

      - Escribir en la celda puntual: sheet.getRange(fila, idCol+1)
        .setValue(nuevoId). No reescribir toda la hoja.

2.4 Respuesta JSON nueva (contrato con el frontend):
      {
        ok: true,
        encontrado: true,
        tipo: 'organizador',
        estado: null,
        motivoRechazo: null,
        nombres: 'Nombre Apellidos',
        codigo: '231212',            // código universitario (si existe)
        comision: 'Actas y Archivos',
        idOrganizador: 'ORG-0007'
      }
    Los inscritos normales seguirán respondiendo tipo:'inscrito'
    (agregar ese campo para distinguir; el JS viejo no se rompe porque
    ignora campos nuevos).

2.5 Orden en doPost():
      1) validar DNI
      2) buscarUltimaPorDNI()  -> si hay, responder inscrito (como hoy)
      3) buscarOrganizadorPorDNI() -> si hay, asignar ID y responder
         organizador
      4) si nada -> { ok:true, encontrado:false, ... }
